## Why

新平台面向外部用户分层开放：免费、VIP、SVIP 与管理员看到的页面、历史深度和明细不同，管理员需要能自行调整；VIP/SVIP 不接支付，只通过邀请码获得；数据是核心资产，需要抵御脚本批量抓取和前端逆向。目前新平台只有一个可选的全局访问令牌，没有用户体系，也没有按角色裁剪数据的能力。

## What Changes

- 用户与角色：免费、VIP、SVIP、管理员四类内置角色（不可删除）；角色 = 权限点集合；管理员可在后台自定义角色的权限点与数值型限额（如可查看历史天数），也可新建自定义角色（如"体验 VIP"）。
- 权限点：页面级（六个主题页）、数据级（历史天数、个股明细开关）、客户端级（网页/小程序可见范围）。
- 邀请码：管理员生成，指定目标角色、有效天数、可用次数、过期时间；用户兑换后升级，到期自动降级为免费；无任何支付对接。
- 登录：账号 + 密码（慢哈希）；短期访问令牌 + 可轮换刷新令牌；登录失败限次与锁定；登出与改密使令牌失效。
- 服务端权限裁剪：接口按角色返回字段与日期范围；前端隐藏仅为体验。
- 防逆向与防爬：生产前端混淆与去 sourcemap；请求签名（时间戳 + 随机数）防重放；按用户与 IP 限流与异常封禁；页面水印；包内无任何上游 Key。
- 管理后台：用户管理、角色与权限点配置、邀请码管理、登录与兑换记录、封禁。
- 审计：登录、兑换、权限变更、管理操作留痕。
- 账号共享限制：每个账号可同时在线的会话数可按角色配置，超出时踢出最早会话。
- 邀请码防爆破：兑换按用户与 IP 限次，连续失败临时冻结兑换。
- 找回与重置：无邮件/短信服务，由管理员重置密码（强制下次登录改密）。
- 用户协议与隐私政策：注册时必须勾选同意；只收集账号所需最少信息；说明数据仅供参考、不构成投资建议。

## Capabilities

### New Capabilities
- `insight-access-control`: 角色与权限点模型、管理员自定义、服务端裁剪、权限变更生效语义。
- `insight-invite-membership`: 邀请码与会员期限、到期降级。
- `insight-auth-session`: 注册登录、令牌、锁定与审计。
- `insight-anti-scraping`: 签名、限流、封禁、混淆与水印。

### Modified Capabilities
（无）

## Impact

- 代码：新增 `backend/insight_api/{auth,rbac,invite,security,admin,store}`；模块投影接入权限裁剪；前端登录/兑换/管理页与请求签名。
- 数据：新增本地数据库（默认 SQLite，经仓储接口隔离，可换服务端数据库）。
- 依赖：密码哈希库、JWT 库、前端混淆构建插件。
- 不含：支付、邮件/短信验证（无对应服务，注册以限流与可选邀请码注册开关抵御滥用）。

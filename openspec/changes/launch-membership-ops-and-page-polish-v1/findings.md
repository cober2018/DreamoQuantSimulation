# 发现与决策

## 关键决策

| 决策 | 原因 |
|---|---|
| 收费走线下收款、后台开通，不接在线支付（用户 2026-10-22 选定方案 A） | 不需要支付资质，可以立即上线；`grant_membership(source=...)` 已为支付回调预留入口 |
| 后台开通拒绝降级（409）；邀请码低等级只延长不降级 | 后台误操作不能缩短用户已付费的时长；邀请码沿用第四期行为，避免改变已发出码的效果 |
| 开通记录只追加，记错用冲正 | 收入流水要能审计 |
| 邀请码兑换金额记 0 | 约定线下收款统一走"开通"，邀请码只用于赠送和试用，不重复计收入 |
| 锁定预告的等级用 `perm_min_role`（按角色计算），不按上架套餐计算 | 套餐默认不上架，按套餐计算会让预告页显示不出等级 |
| 后台用户行去掉原来的"设会员角色"下拉，改为"开通/续期"和"清除会员" | 原入口绕过开通记录，会导致收入对不上 |
| 缺数据日只报 `latest_available_date`，不返回那天的数据 | 不能用其他日期的数据冒充所选日期 |
| 小程序不做"跳到最近有数据日"按钮 | 小程序没有日期选择，总是请求最新数据；最新一行就是最近有数据的日期 |

## 2026-10-22 上游行业 ADS 三表拆分的影响核对

- 上游变化：`review-industry` 升到 v2，返回 344 列，去掉了 `stock_ranking_results` 和 `stock_risk_permissions` 两块嵌套明细；另外新增两个明细服务 `review-industry-stock-ranking`、`review-industry-stock-risk-permission`。
- 本项目只用 `review-industry` 汇总接口，并按 `modules.py` 的 `INDUSTRY_FIELDS`（25 个字段）白名单取值。被去掉的两列从来不在白名单里，夹具里也没有这两列，所以不用改代码。
- 上游新定义的 409（引用批次缺失或不一致）会被 `HttpSource.page` 当作非 200 抛出 `UpstreamError`，网关转成 502"数据服务暂不可用"。这样不会被当成"数据暂缺"，和上游说明里"409 不应当作合法空集合"的要求一致。
- 决定不接两个新明细服务：内容是个股层面的评分、新增许可和敞口上限，属于本平台合规上不迁入的内容（会触发 `FORBIDDEN_KEY_RE` 里的 opportunity、risk_score、budget 等关键词）。

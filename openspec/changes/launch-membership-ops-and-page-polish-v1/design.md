## Context

- 第四期已经实现：角色和权限点（`roles`、`role_permissions`），用户的 `member_role` 和 `member_expires_at`，邀请码兑换（`redemptions`），审计日志，以及按到期时间自动降级（`effective_role` 读取时判断）。
- 管理员现在用 `update_user` 直接改会员角色和到期时间。这种改法不记金额、不记来源，续期时还要自己算新的到期日。
- 数据页都套在 `PageFrame` 里。上游没有当天数据时，接口返回 `status=empty`，页面只显示一句话。
- 上游数据中台正在改造，2026-10-21 起部分服务可能没有数据或数据不全。

## Goals / Non-Goals

**Goals：**
- 线下收款后，管理员在一个界面里完成开通或续期，同时留下金额记录。
- 免费用户知道会员能看什么、怎么开通。
- 缺数据时如实显示，并给出跳到最近有数据日期的路径。
- 列出上线必须做的事项，逐项可以勾选。

**Non-Goals：**
- 不接微信支付、支付宝，也不放收款码。
- 不做优惠券、分销、自动续费。
- 不做短信或邮件提醒，只做站内提醒。
- 不改上游数据中台，也不补算缺失的数据。
- 不新增数据内容条目（CNT），页面优化只调整已审定内容的展示。

## Decisions

1. **套餐单独建表**（`plans`：id、name、role、duration_days、price_cents、listed、sort、note）。
   - 价格不写死在前端，因为管理员要能随时调价、上下架。
   - 不把价格挂在角色上：同一个角色可能有月卡、季卡、年卡。

2. **统一开通函数** `grant_membership(user_id, role, days, *, source, plan_id, amount_cents, channel, note, actor)`。
   - `source` 取值：`admin`、`invite`、`payment`（`payment` 留给将来接入在线支付）。
   - 到期时间这样算：
     - 当前会员同级而且还没到期：从原到期时间往后加。
     - 升级到更高等级：从现在开始算（高低按现有 `_rank`）。
     - 降级到更低等级：拒绝，提示管理员改用"清除会员"再开通，避免不小心缩短用户已买的时长。
   - 邀请码兑换改成调用这个函数，这样开通记录统一在一张表里。原 `redemptions` 表保留，旧记录照样能查。
   - 写进 `membership_grants` 表（不可修改，只能追加）。记错了不改原记录，而是追加一条 `channel=correction`、金额为负数的冲正记录，保证收入流水可以审计。

3. **收入合计只算 `membership_grants.amount_cents`**，按时间区间汇总。
   - 邀请码兑换的金额记 0。约定：线下收款统一走"开通"，邀请码只用于赠送或试用，所以兑换不产生收入。

4. **锁定预告完全由前端静态内容生成**。
   - 每个页面的介绍、包含的指标名称、所需等级，写在前端的一个对照表里。
   - 预告不请求数据接口，所以服务端权限边界不受影响。
   - 所需等级取自 `/auth/me` 新增的 `perm_min_role`（各权限点的最低非管理员角色，按 `_rank` 排序）。不按上架套餐计算，因为套餐默认不上架，那样锁定页就显示不出等级；管理员调整权限后前端也不用改代码。

5. **缺数据的处理**：
   - 后端在 `status=empty` 时，加一个 `latest_available_date` 字段。取法：去掉 `trade_date` 参数，再向上游请求一次（上游默认返回最新一行），取出那行的日期。不额外推断，也不插值。
   - 前端 `PageFrame` 显示"该日数据暂缺（上游数据维护中）"和"查看 {日期}"按钮。
   - 各部分日期不一致时，用各部分自己的 `source_date` 或 `trade_date` 标注。

6. **到期提醒**：
   - `/auth/me` 已经返回 `member_expires_at`，前端算剩余天数，7 天及以内就提示。
   - 后台的"即将到期"筛选由 `list_users` 新增 `expiring_within_days` 参数实现。

## Risks / Trade-offs

- [风险] 对外展示价格和收费，可能被认定为有偿证券信息服务，会涉及资质。→ 上线检查清单单列"资质与主体"一项，由用户确认后再把套餐上架。系统默认所有套餐不上架。
- [风险] 补拉 `latest_available_date` 会多一次上游请求。→ 只在 `empty` 时发生，并且复用已有的 TTL 缓存。
- [取舍] 降级开通直接拒绝，管理员要多点一步。换来的是不会误删用户已付费的时长。
- [风险] SQLite 是单实例。→ 维持现状；README 里已经记录了多节点部署前要换数据库。

## Migration Plan

- 启动时 `CREATE TABLE IF NOT EXISTS` 新建两张表，老数据库直接可用。
- 回滚：回到上一个版本即可。新表不影响旧代码运行。

## Open Questions

- 套餐的具体价格和天数：上线前由用户在后台填写，代码里不预设。
- 客服联系方式（微信号或二维码）：由用户提供，放进套餐页的配置项，不写进代码。

## 协议层错误

请求本身被拒绝时，返回 JSON-RPC 的 `error`：

| 代码 | 含义 | 怎么处理 |
|---|---|---|
| `-32001` | 令牌无效、已过期或已吊销（HTTP 401） | 在账号页重新创建令牌，更新客户端配置 |
| `-32003` | 无权访问：账号已停用、需要先在网页修改初始密码，或账号未开通 MCP（HTTP 403） | 按返回的说明处理；仍不行请联系我们 |
| `-32029` | 请求过于频繁，超过每分钟或每天的上限（HTTP 429） | 等待返回里 `Retry-After` / `retry_after` 的秒数后再试 |
| `-32700` | 请求不是合法的 JSON | 检查客户端配置；一般由客户端自动处理 |
| `-32600` | 不是有效的 JSON-RPC 请求（不支持批量） | 同上 |
| `-32601` | 不支持的方法 | 升级客户端，或确认调用的是工具而不是其他能力 |
| `-32602` | 未知工具 | 先调用 `list_datasets` 或重新获取工具列表 |

## 工具层错误

工具调用返回 `isError: true` 时，`error` 字段说明原因：

| 情况 | 怎么处理 |
|---|---|
| 参数错误（缺参数、取值无效、日期格式不对） | 按提示修正参数，日期写成 `YYYY-MM-DD` |
| 当前等级不能使用该工具，或日期超出可看的历史范围 | 换成当前等级可读的工具或日期，见 [价格与权益](/pricing/) |
| 数据服务暂不可用 | 稍后重试 |
| 数据校验未通过，本次不返回数据 | 稍后重试；持续出现请联系我们 |

某个交易日没有数据时，工具不报错，而是返回 `status=empty` 和最近有数据的日期 `latest_available_date`。
